# ADR-0002 — Render shell payloads; never rewrite the user's script

- **Status:** accepted
- **Date:** 2026-08
- **Deciders:** Dime

## Context

`shell.run` receives a script written by a model that was told "run this in bash". To make
results parseable we need to know the exit code, the final cwd, and sometimes the
environment. Three ways to get them:

1. wrap/rewrite the body (inject `set -e`, re-indent, append `; echo $?`);
2. wrap it *around* — fixed preamble, verbatim body, fixed appendix;
3. require the script to cooperate (a magic final line, or a function contract).

Option 1 is where portability tooling goes to die: `set -e` inserted into a script that
relies on a failing grep changes its meaning; re-indenting a Python heredoc breaks it;
"we normalised your `&&` chains" is an unanswerable review comment when an agent's diff
against a file does not match what it ran. Option 3 fails with autonomous agents, which
will forget the convention under pressure.

## Decision

`dialect.render()` is **preamble + verbatim body + appendix**, symmetric across bash,
PowerShell and python:

- the body is only ever normalised for line endings (`\r\n` → `\n`) and given a trailing
  newline — no re-indentation, no insertion, no `set -e` rewrite;
- strictness lives in the **preamble** (`set -euo pipefail`, `$ErrorActionPreference =
  'Stop'` + `Set-StrictMode`), togglable per call with `strict: false`;
- the appendix reads `$?` as its *first* statement (`SK1_RC=$?`), so an abort mid-body
  still yields a parseable exit code;
- the appendix is generated by a trap (bash `trap '__sk_finish "$?" 1' EXIT/INT/TERM`,
  PowerShell a `finally`), so `exit 3` inside a subshell cannot skip it;
- delivery is a script **file** under the state dir, never `-c`, so the body is not parsed
  twice by a shell;
- dialect-specific parser quirks are patched in the *payload*, not in the body: Windows
  PowerShell 5.1 gets a UTF-8 BOM because it reads BOM-less files as ANSI; 5.1 gets
  `Set-StrictMode 2.0` instead of `Latest`; `-ExecutionPolicy Bypass -NoProfile
  -NonInteractive -NoLogo`.

## Rejected alternatives

- **Rewrite `&&`/`||` into `if` blocks for 5.1 compatibility.** Correct and unreadable;
  now the script an agent reasoned about is not the script that ran.
- **`sh -c` inline delivery.** One more quoting pass over untrusted text; a backtick in a
  `fs.read` output that ended up in a script becomes command injection in *our* layer.
- **Return values through a temp JSON file the script must write.** Reintroduces the
  convention option 3 rejected; `expects: "json"` on stdout is enough.

## Consequences

- (+) What ran is inspectable: `shell.run {keep_script: true}` returns `data.script_path`,
  the exact payload file, readable through `fs.read`. A failure is therefore
  byte-for-byte reproducible, which is what P4 replay depends on.
- (+) Adding a dialect = adding a preamble/appendix pair, not touching call sites.
- (−) The preamble must be *conservative*: it cannot assume `bash` features when the
  dialect is `sh` (e.g. env capture via `compgen` is bash-only, so `sh` reports
  "cwd-only here" in `notes` rather than pretending).
- (−) If a body itself prints a line shaped like our sentinel, `parse_sentinel` must
  tolerate it — the per-call random token (ADR-0003) is the mitigation, and the parser
  ignores lines whose token does not match.

## Verification

`tests/test_dialects.py` asserts payload *strings* (preamble order, appendix first
statement, BOM presence for 5.1, verbatim-body guarantee with a script containing `&&`,
heredocs and CRLF), `tests/test_shell_runner.py` runs the same contract against live bash
including `exit 3`, `kill -9`, `set -e`-aborted and unterminated-pipe cases.
